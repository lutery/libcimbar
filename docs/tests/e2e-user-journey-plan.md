# 真实E2E用户操作测试计划

阶段4.7，2026-10-18。用户此前已明确要求贴合真实操作；本端继续编制该计划。全部产品场景NOT RUN，执行者未运行时为null。

输入：[实施计划](../plans/2026-10-18-desktop-receiver-implementation.md)、[确认需求](../requirements/requirements-spec.md)、[验收基线](../plans/test-acceptance-plan.md)、[集成验收定义](acceptance-tests.md)。不复制TDD正文，真实字节/竞态支撑检查引用IAT。

## 共用前置、工具和证据

先完成严格EOF/资产配对和必要单元/集成。实施方在同一本地电脑实际运行原发送窗口与新接收端，录像必须录自真实发送画面。云桌面客户端不要求在浏览器中，真实现场选择Citrix/RDP等客户端窗口。

实际步骤以正常有界面Edge、真实选源/文件/保存对话框和专有测试目录执行。可用UI自动化做页面点击和截图，原生对话框不能操作时安排实际人工；直接调用内部函数、自动授权模拟屏幕、fake句柄只能算IAT，不能记真实用户点击。系统模态阻塞页面时先取消返回再停止；模态未返回时内部停止由IAT-03/05验证。

每项保留包/JS/WASM/profile摘要、环境/DPI/zoom、来源类型/自然尺寸/源和处理fps、session/attempt、实际点击/界面/清理日志及外部原文件/最终磁盘SHA-256。两类文件双输入各3干净会话、10轮混合生命周期、最终包复验沿用基线；性能阈值未确认只报测量。

手动场景不能仅靠自动化脚本退出0通过。自动化骨架是“打开普通页面 -> 执行下列真实动作 -> 断言界面 -> 取得实际磁盘文件 -> 外部hash -> 记录证据”；实现方在阶段5选择可用工具，不额外引入产品UI测试入口。
