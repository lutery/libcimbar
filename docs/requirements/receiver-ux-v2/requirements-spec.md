# 接收器体验迭代 v2 — 需求规格（已确认）

状态：阶段1已确认，用户已授权进入阶段2系统设计。Q-001回答“按照推荐执行”，并确认其余无问题。本规格是设计与规划基线，不是已实现或已验收记录。原始输入见[user-feedback](user-feedback.md)，代码取证见[可行性](feasibility.md)。

## 已明确目标与角色

使用者在宿主机接收云桌面内部发送的文件。现有传输已由用户实际使用成功，本轮目标是让用户知道是否正在收到数据、接收情况与进度，并能理解下一步操作。只采用经代码与必要探针确认可行的反馈，不能用动画或虚构数字代替事实。

### 已明确的功能需求

- FR-UX-001：接收过程中提供可理解的接收活动反馈，解决无法判断是否在接收的问题。
- FR-UX-002：提供有明确含义且来自真实观测的速度信息。
- FR-UX-003：提供有明确含义且来自真实观测的进度信息；不能确认时如实说明。
- FR-UX-004：基于现有接收流程改善用户操作体验，结合代码判断可行性后再确认范围。
- FR-UX-005：保留“实时抓屏”和“录像导入”两个独立按钮，两种接收方式都增加反馈；接收中的禁用互锁沿用既有规则。

### 已确认首轮范围

中文主操作区；准备/等待有效码/收到数据/暂无新增/可保存/保存中/已保存等提示；已用时、近期数据识别速率、可判定时的重建进度估计；实时抓屏与录像导入均适用；录像位置与文件进度分开；诊断日志折叠或次要展示；错误/取消后的下一步清楚可见。

保持原发送端和既有传输/保存协议，优先复用现有WASM report。report缺失、格式异常或多流身份不明时退化为活动与时长反馈，接收本身继续。准确原文件剩余字节和稳定剩余时间当前没有足够遥测依据，不纳入本轮承诺。

## 非功能要求

- NFR-UX-001 真实性：捕获帧、识别数据、新块增长、产物就绪、磁盘保存分别表述；进度/速率的单位及估计性质可见。
- NFR-UX-002 兼容性：不改变原发送端协议与Mode B既有兼容性，不放松严格EOF、预算、单在途、旧会话隔离和保存重试规则。
- NFR-UX-003 性能：状态刷新不驱动额外抓帧或并发解码；遥测读数有界、重绘节流，具体更新频率与回归阈值在设计/验收计划确定。
- NFR-UX-004 可访问性：主要状态有文字，不能只靠颜色或闪烁；高频速度变更不逐帧打扰屏幕阅读器；控制保持键盘可操作。
- NFR-UX-005 隐私与生命周期：遥测局限当前本地会话，不上传内容；新会话清零，旧回调/计时器不能污染新会话，结束后停止不必要刷新。

## 用户流程

选择抓屏/录像→准备→等待可识别数据→识别到数据且显示观测→进度可能增长或暂停→真实重建成功→提示可保存→用户保存→写入与close成功后显示已保存。无新数据提示提供检查源/码制/可见性等可操作建议；不能武断判定网络断开。录像耗尽但无产物维持未完成语义。停止、重新开始与保存取消沿用既有规则。

## 验收标准（AC-015～024，已确认）

| 编号 | Given / When / Then |
|---|---|
| AC-015 | Given已选择源但没有有效码，When显示接收活动，Then明确等待有效数据；仅有图像帧不显示已取得文件进展 |
| AC-016 | Given单个可判定流，When新块/重复块到达，Then重建估计按真实report变化，重复不虚增；缺失/异常/多流无身份时显示不可判定，不冒认其他文件进度 |
| AC-017 | Given可解码结果，When显示近期速度，Then单位与“数据识别速率（含冗余）”含义明确；不把捕获RGBA或重复字节声称为有效文件字节；无新结果时停止虚显旧速率 |
| AC-018 | Given同一活动会话，When没有新snapshot或无有效数据，Then时长/等待反馈仍按设计周期更新；首次等待与曾接收后暂停分别可理解，阈值不触发自动失败/重启 |
| AC-019 | Given录像导入，When展示处理位置，Then明确该位置不是文件完成比例；视频到尾而未重建时不显示成功 |
| AC-020 | Given真实产物尚未完成或未写盘，When显示完成提示，Then分别只在严格完成后提示可保存、write及close成功后提示已保存；取消/失败保留可重试 |
| AC-021 | Given停止/晚回调/开始新会话/双输入切换，When展示遥测，Then新会话清零，旧进度与计时器不串入，保存边界和按钮互锁不变 |
| AC-022 | Given中文使用者，When通过主操作区接收和保存，Then无需阅读英文调试日志即可判断当前状态与下一步；文字/键盘/辅助技术反馈成立 |
| AC-023 | Given原有单在途解码，When启用遥测和UI刷新，Then不新增并发或积帧，遥测错误不阻断接收；开销按冻结方法实测，不以单元测试替代性能证据 |
| AC-024 | Given整改后构建，When按真实抓屏、录像、停顿恢复、保存重试与旧关键旅程验收，Then输出外部SHA相等，体验提示与同一运行观测相符；本地与用户现场证据分列 |

旧AC-001～014仍作为基础回归约束；以上10条随本次范围确认冻结，由阶段2设计与阶段4.x测试规划落实。

## 数据、权限与集成边界

现有frame-result、session snapshot、WASM report、录像位置为候选数据源；不引入服务器或遥测上传，不新增权限。系统选择器仍由用户操作触发，状态显示不得改变会话成功/失败条件。UI具体字段和消息扩展在阶段2/2.5定义。
