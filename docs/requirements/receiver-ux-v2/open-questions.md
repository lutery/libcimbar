# 问题与回答

## Q-001 首轮体验范围（已确认）

- 问题：是否采用“中文操作界面 + 接收状态分层 + 已用时 + 近期数据识别速率 + 有依据的重建进度估计”，覆盖实时抓屏与录像导入？
- 影响：决定展示范围、消息/状态扩展与验收；用户选择推荐范围。
- 推荐：采用[需求草案](requirements-spec.md)首轮候选范围，优先复用现有report；缺失/多流时显示暂不可判定。
- 替代A：先只改善状态提示与操作引导，速度/估计进度后置。
- 替代B：用户补充希望纳入或删除的范围，再冻结。
- 决策人：用户。用户已在本文件填写回答，并通过后续消息确认其余无问题、授权进入下一阶段。
- 回答（保留用户原话）：按照推荐执行
- 结论：采用推荐首轮范围；实时抓屏与录像导入两个按钮均保留。
- 后续授权（用户原话）：待决策问题我已经做了决策，其余的没问题了，你看下，没啥问题就进入下一个阶段
- 当前无待答需求问题；技术参数由设计/实测落实，不再让用户重复确认实现细节。

## 由后续设计/实测确定，无需让用户决定实现细节

刷新频率、速度窗口、首次等待和暂停提示阈值、report缓冲上限、多流/解析失败退化、无障碍播报节流、录像位置采样、开销验收方法。阈值在对应阶段明确后才能作为验收标准，不先伪称已有数据。
