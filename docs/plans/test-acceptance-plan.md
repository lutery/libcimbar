# 真实操作测试与验收方案

本方案补充[路线图](roadmap.md)阶段3的验收基线，依据[确认需求](../requirements/requirements-spec.md)、[原始回答](../requirements/open-questions.md)及[模块契约](../design-catalog/module-contract-error-matrix.md)。2026-10-18 编制；**全部产品用例尚未执行，初始结果均为 NOT RUN**。文档检查通过不表示产品通过。

按更新版dev-pipeline，Codex阶段4/4.5/4.7把本方案纳入[实施计划](2026-10-18-desktop-receiver-implementation.md)、[TDD](../tests/test-plan.md)和[正式E2E](../tests/e2e-user-journey-plan.md)；Claude从阶段5执行，不能删减本方案中的必测用户路径。所有执行节点仍待实际完成。

## 责任、测试层级和结论

| 层级 | 执行者与输入 | 可以证明什么 |
|---|---|---|
| 文档/schema检查 | 规划方；文档、合成元数据 | 追踪和结构正确；不能证明解码、授权、保存或用户可用性 |
| IAT集成 | 实施方；真实C/WASM/Worker，必要的受控故障注入 | 字节、边界、时序和失败分支；注入项明确标unit_integration |
| UAT-L本地操作 | 实施方；同一台电脑的原发送端窗口、新接收端、真实录像和磁盘 | 实际操作者可完成本地双输入、停止重启及保存；不是云桌面现场结论 |
| FAT现场 | 用户；真实云桌面客户端及云端原发送端 | 对应客户端/显示设置/样本范围内的现场结果；本地PASS不能代填 |

实施方负责先交付完整本地结果，不能把本地基本功能留给用户调试。工具不能操作系统对话框时，应补充实际人工执行或可用工具并留证，缺失时保持NOT RUN/BLOCKED。UI自动化、手工操作可以结合；每个真实系统路径必须有人或工具实际执行。模拟捕获源、直接喂PNG/帧缓冲、直接调用解码函数、模拟保存句柄均不能替代UAT-L。

每项分别报告功能结果、测量状态及现场状态。必测项任何一项FAIL或未执行，不得用总通过率覆盖。功能满足且证据充分才PASS；性能阈值未确认时标“已测量/目标未评定”，不算性能PASS。

## 执行前准备与样本

1. 固定构建提交、页面/JS/WASM整套摘要、profileId、支持矩阵和使用说明；先完成T1.2.a严格EOF及匹配WASM门槛，再运行完整用户路径。
2. 第一轮以Windows桌面Edge、原发送模式B为基线。记录实际浏览器/系统版本、CPU/内存、显示器、系统DPI、浏览器缩放、源窗口/捕获自然尺寸；从操作者当前正常桌面设置开始，不能暗中调整到开发者专用配置才声称可用。
3. 同机打开原项目发送端，放在接收端之外的独立窗口。发送源可以是独立浏览器窗口；真实现场则是Citrix/RDP等**桌面客户端窗口**，不要求远程桌面运行在浏览器中。选择窗口和整屏分别按实际支持矩阵验证，不能把只测标签页写成支持任意客户端窗口。
4. 新接收端从候选/最终包按用户说明启动，使用正常有界面的浏览器；不依赖开发控制台、手改资源路径、仓库工作目录或注入测试帧。自动授权、自动选源的测试结果另记，不能替代真实选择器流程。
5. 测试保存目录仅用本轮专有目录；原样本独立只读保留。所有重名覆盖试验使用可丢弃哨兵文件，不对用户原文件试验。

| 样本ID | 内容与准备 | 作用 |
|---|---|---|
| D-C | 起点64 KiB可压缩真实文件，记录生成方式/种子和外部SHA-256 | 高压缩比、最终解压字节正确 |
| D-N | 起点256 KiB已压缩或难压缩真实文件，记录来源/生成种子和外部SHA-256 | 非高压缩比路径，不能只测重复字符 |
| D-A / D-B | 分放两个目录，basename相同、字节数相同、内容和SHA-256不同 | 旧会话/旧File对象/旧Blob串入检查 |
| D-EXT | 稳定后1 MiB、4 MiB两类数据，受已核实协议/profile限制 | 测量扩展，不能据样本大小声称最大容量 |
| V-GOOD | 实际录制原发送窗口，覆盖足量编码帧及余量；分别对应D-C/D-N | 正常录像；记录录制工具、容器/编码、源尺寸/帧率和时长 |
| V-SHORT | 可正常打开播放、但经对照证明确实缺少足量数据的录像 | 合法容器不足数据；不能仅把文件字节截断当媒体EOF |
| V-LAST | 成对真实编码画面录像：保留最后关键有效帧能完成，去掉该帧不能完成 | 最终帧/在途解码/EOF排空；需保留生成与对照证据 |
| V-BAD | 空文件、非视频文件、损坏容器和当前浏览器实际不支持的媒体各自登记 | 媒体失败与能力提示；若某候选格式实际支持，不得称其“不支持” |

样本起点是规划建议，可按首轮实测调整但必须记录原因、实际字节与新哈希；不得通过只选极小文件隐去正常路径失败。V-LAST建立可重复的真视频对照；只通过控制Worker回调构造的竞态属于IAT-03，不能写成V-LAST实际操作通过。

外部哈希对**原文件和最终磁盘文件**分别计算，不能用应用自报哈希或Blob代替。PowerShell示例（执行时替换成真实路径）：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\验收样本\原文件.bin'
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\验收结果\已保存文件.bin'
```

正常实时、正常录像在主基线下分别对D-C/D-N执行3个干净会话，即至少12次完整往返；每次均独立保存、外部哈希和计时。再执行UAT-L20的10轮混合生命周期。新增宣称支持的浏览器/模式/录像格式须逐组合执行双类样本的适用正向路径及受影响异常；不支持项明确标范围，不能删掉整个录像功能。

## 本地真实操作用例（实施方执行）

所有用例保留实际步骤、界面状态/录像、对应日志及前后文件证据。预期界面文字可由实现确定，但必须表达下述含义；仅控制台可见、用户需要猜测的状态不算满足。

### UAT-L01：从干净交付目录首次启动

- 前置/追踪：候选包及其用户说明；AC-001、AC-003、AC-005、AC-013；T2.1.a/T5.1.a/T5.1.c。
- 操作：①解压到含中文和空格的新目录。②从非仓库工作目录严格照说明启动。③普通Edge打开给出的入口，查看双输入、开始/停止和保存说明。④完成UAT-L03、UAT-L14各一次。
- 预期/失败：资源和WASM自动正确加载，真实双输入可用；不能靠手改路径、手工启动未写入说明的服务、控制台授权或复用开发服务器补救后记PASS。缺少前置应明确提示。
- 证据：包摘要、启动命令/入口、目录、浏览器状态、两个实际落盘哈希；首次修复前的失败也保留。

### UAT-L02：启动失败与退出恢复

- 前置/追踪：文档列出的依赖/端口；AC-005、AC-006、AC-013；T2.1.a/T5.1.a。
- 操作：①在独立测试环境尝试缺少必要运行时、测试端口被占用。②按提示恢复依赖/选可用端口。③正常启动、退出、再次启动；测试服务退出时页面如何提示及恢复。
- 预期/失败：提示有实际可执行步骤；不得长期白屏、静默挂起或自动终止无关进程。包自带运行时则以干净环境验证自带路线，不要求人为卸载系统软件；分支不适用须解释。
- 证据：实际故障条件、终端/页面提示、恢复记录；无法制造的系统分支单列注入，不算实际执行。

### UAT-L03：正常实时接收、保存和校验

- 前置/追踪：D-C/D-N、原发送B、主基线；AC-001、AC-002、AC-003、AC-004、AC-010；T2.1.b/T2.1.c/T4.1.b。
- 操作：①原发送端加载样本。②用户点击实时开始，在真实选择器选发送端独立窗口。③等待重建，查看状态。④用户点击保存、在系统对话框选专有目录并确认。⑤外部核对保存文件大小与SHA-256。⑥停止、确认清理，再换样本；按规定重复。
- 预期/失败：有效帧/进度、待保存和已保存有明确区分；write及close结束前不得显示保存成功。两个哈希必须相等，单有下载按钮/Blob/Ready截图不算通过。
- 证据：选择来源过程、sessionId、自然尺寸/模式、各时点、实际落盘路径/尺寸及外部哈希原始输出。

### UAT-L04：取消捕获后重新开始

- 前置/追踪：无活动会话；AC-006、AC-007；T2.2.a/T2.2.b/T4.1.b。
- 操作：①点实时开始，在系统选择器取消。②返回页面查看提示。③重新点击开始并选择正确窗口，完成保存。④若环境提供独立拒绝授权路径，单独执行并记录；未提供则用IAT验证拒绝分支。
- 预期/失败：取消后可理解且可重试，无残留加载/旧进度，重试可真实成功。不能把“取消”证据写成所有授权拒绝均已实测。
- 证据：对话框取消和重新授权记录、新旧会话、保存哈希。

### UAT-L05：选错窗口、空白窗口和无有效数据

- 前置/追踪：另开无编码内容的窗口；AC-006、AC-007；T2.2.b/T4.1.b。
- 操作：①实际选择空白/错误窗口并等待当前profile的无数据提示期限。②观察状态后点停止。③重新选原发送端，完整接收保存。
- 预期/失败：无数据提示并提供检查来源/模式和停止入口；不能虚构“必为权限故障”、报成功或刷错误风暴。正确重选后可用。
- 证据：错误来源画面、等待时长/提示、恢复会话和哈希。

### UAT-L06：系统停止共享/源窗口关闭

- 前置/追踪：接收尚未完成的D-A；AC-006、AC-007；T2.2.a/T2.2.b/T4.1.b。
- 操作：①传输中用浏览器/系统“停止共享”控件结束源；另会话关闭发送源窗口。②查看页面与共享指示。③确认清理后发送同名同大小D-B并保存。
- 预期/失败：源结束/当前未完成准确呈现，可干净重启；D-B哈希必须匹配B且不等于A。不支持某种源关闭通知时也不能假完成，须能停止恢复。
- 证据：外部停止/关闭动作、资源清理、新会话及A/B/输出三方哈希。

### UAT-L07：应用内停止、重复点击与重启

- 前置/追踪：D-A/D-B；AC-007；T2.2.a/T4.1.b。
- 操作：①A传输中点停止，并快速重复点击停止/开始。②按界面等待清理完成。③新会话加载B；快速重复开始，完成保存。
- 预期/失败：只有一个活动源和Worker，停止后捕获指示结束；清理中不能再建新会话；新进度从零开始、无A产物和晚到错误覆盖B，不出现双选择器。实际资源计数由集成日志辅助验证。
- 证据：点击录像、状态/资源时间线、B外部哈希；压力点击不能由仅发送内部命令冒充。

### UAT-L08：发送模式不匹配后恢复

- 前置/追踪：接收基线B，原发送端另一实际可用模式；AC-006、AC-013；T2.2.b/T4.2.b。
- 操作：①发送非B数据，接收仍B；真实捕获观察无数据/失败状态。②停止后改回B完成同一原文件往返。
- 预期/失败：不匹配不能显示完整成功；提示检查模式，不要求仅凭画面准确诊断所有原因。不得为此把未验证模式列成接收支持项。
- 证据：发送/接收模式、状态、恢复哈希；候选模式若不存在说明原因，IAT补分支，不伪造现场模式测试。

### UAT-L09：当前DPI、缩放、尺寸与预算

- 前置/追踪：记录当前正常桌面配置及profile；AC-001、AC-006、AC-012；T2.1.b/T2.2.b/T4.2.a/T4.2.b。
- 操作：①保持操作者当前默认DPI/缩放完成实时往返。②调整发送源和接收端窗口大小，保持编码区可见，再往返。③对宣称支持的100%/125%/150%系统DPI及浏览器缩放逐项测试，记录实际可用组合。④有真实可达的超像素预算来源时选择并观察拒绝/恢复。
- 预期/失败：自然像素与缓冲一致，不偷偷缩图后仍宣称正常；正常布局可用，超预算有说明和恢复办法。未测DPI不写支持；不能只在隐藏的特殊设置可用。实际未能制造的精确边界归IAT-02，不能假记实际超限通过。
- 证据：系统/浏览器设置、可见编码区、自然分辨率/profile、输出哈希或实际预算提示。

### UAT-L10：切换焦点、遮挡、最小化与恢复

- 前置/追踪：已能正常窗口捕获；AC-001、AC-006、AC-007；T2.2.b/T4.1.b/T4.2.b。
- 操作：①正常接收中切回接收页面查看进度并保存。②另轮覆盖源窗口，再还原；另轮最小化源窗口，再还原。③必要时按提示停止重试。
- 预期/失败：至少支持一条用户正常切换到接收页并完成保存的工作路径。遮挡/最小化是否持续供帧据实记录；停止供帧应不假成功且能恢复，不强求平台没有的后台捕获保证。文档写出验证过的布局和限制。
- 证据：窗口布局/操作录像、输入帧变化、等待提示、恢复及哈希；不能只保留开发者全程盯住源窗口的成功案例。

### UAT-L11：取消保存后无需重传重试

- 前置/追踪：已完整重建的文件；AC-003、AC-004、AC-009；T3.2.a/T4.1.b。
- 操作：①停止发送端动画/关闭发送窗口，保留当前接收会话已重建Blob。②点击保存，在系统对话框取消。③新点击保存，选择目录确认，外部哈希。
- 预期/失败：取消不显示已保存，不销毁可重试产物；无新源/新传输即可保存相同字节。停止发送不等于点击接收端“停止/重置”，后者不承诺保留Blob。
- 证据：发送停止、保存取消与新点击、同一artifactId、新attemptId、实际输出哈希。

### UAT-L12：中文/空格文件名、重名与明确覆盖

- 前置/追踪：带中文/空格basename样本及专有目标目录哨兵；AC-003、AC-004、AC-009；T2.1.c/T3.2.a/T4.1.b。
- 操作：①重建后打开保存对话框，核对建议名。②目标同名已存在时取消覆盖，检查哨兵哈希未变。③再次保存为不同名，核对字节。④仅在专有目录显式确认覆盖另一哨兵，核对最终字节；记录用户自改名行为。
- 预期/失败：原名作为安全basename建议；缺失名时使用说明中的回退名。禁止静默覆盖、路径越界、取消后假成功。外部哈希核对实际所选路径。
- 证据：建议名/重名确认画面、原哨兵和最终文件哈希；缺名/危险路径分支IAT补测。

### UAT-L13：保存重复点击及系统模态交互

- 前置/追踪：已重建文件；AC-003、AC-007、AC-009；T3.2.a/T3.2.b/T4.1.b。
- 操作：①快速重复点击保存，观察是否只出现一个有效保存流程。②对话框打开后取消/关闭，返回页面，再点击停止并等待清理；重启接收另一文件。③另轮实际保存成功后停止，确认文件仍存在且哈希不变。
- 预期/失败：无重复写入或重叠选择器；停止不删除已保存文件。如果系统模态使页面不可点击，不要求用户在模态期间点击停止；“选择器未返回时内部停止”另测IAT-03/05，不能用脚本调用冒充用户点击。
- 证据：完整操作录像、保存次数/attempt日志、清理状态与文件存在/哈希。

### UAT-L14：真实录像导入成功

- 前置/追踪：D-C/D-N的V-GOOD、候选MP4/H.264及WebM/VP8；AC-003、AC-004、AC-010、AC-014；T3.1.a/T4.1.b/T4.2.b。
- 操作：①关闭发送端，确认没有实时捕获。②用户选择录像入口，用实际文件选择流程导入V-GOOD。③等待受控播放/解码完成，保存并计算外部哈希。④按支持格式及规定重复次数执行。
- 预期/失败：无需后台发送/隐藏实时输入即可完成；至少一种真实格式往返通过，发布的每种格式均有实际证据。正常录像仅被加载/播放不算文件接收通过。
- 证据：录像文件摘要及录制信息、发送已关闭、媒体时长/处理时间、保存路径/哈希和输入类型日志。

### UAT-L15：录像选择取消、不支持和损坏后恢复

- 前置/追踪：V-BAD和V-GOOD；AC-006、AC-008、AC-014；T3.1.a/T2.2.b/T4.1.b。
- 操作：①取消录像选择，重新导入。②分别导入空/非视频、损坏、实际不支持文件。③每次失败后导入V-GOOD并保存校验。
