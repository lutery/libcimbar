# 系统设计输入与追踪

阶段 2；2026-10-18。用户已授权无待答问题则进入系统设计。权威需求为 [需求规格](../requirements/requirements-spec.md)，用户原始回答见 [问题与回答](../requirements/open-questions.md)。设计决策不改变需求范围。

## 目标、角色与约束

新增运行在云桌面客户端宿主机上的接收端，同时支持实时抓屏与录像导入，摆脱手机接收依赖。发送端与 cimbar 协议复用原项目，其余尽量不改。浏览器或原生架构可由本阶段根据现有代码和技术依据选择。

角色：接收操作者、发送操作者、实施执行方、真实云桌面验收用户。实施执行方先在同一本地电脑上运行原发送端与新接收端，完成全功能模拟；用户随后完成真实环境测试。

本节点生效的附加指令：双输入、最小变更、单文件会话、停止释放与干净重启、保存失败可重试、外部 SHA-256、两类数据覆盖、容量性能先测后确认。本地模拟和现场验收独立记录。

## Open Questions / Hotspots

没有待用户回答的需求 P0。以下是已批准后测策略下的技术验证点，不代表能力已经通过；系统设计明确方案和失败出口，实施必须核验。失败时先在本接收方案内定位，不能自动扩展原协议或发送端。

| 热点 | 不确定性 | 收敛方法 / 不满足时的结果 | 需求追踪 |
|---|---|---|---|
| H-CAP | 客户端能否被抓取，窗口遮挡/最小化和远程压缩后的信号质量 | 本地真实窗口模拟，后续用户现场验证；无有效画面只报告未检测，不推断具体原因 | V-001、V-004；AC-006、AC-011 |
| H-VIDEO | 视频格式支持及浏览器帧回调遗漏 | 首轮 MP4/H.264、WebM/VP8 分别验证；记录实际帧时间及跳帧；只发布通过组合，录像 EOF 不完整即失败 | V-001～V-003；AC-008、AC-014 |
| H-MEM | 固定 WASM 堆、像素缓冲与解压产物内存预算 | 先测典型帧/样本；分配失败中止，不静默缩放或截断；容量上限按实测确认 | V-002、V-003；AC-012 |
| H-ASSET | 工作树没有生成 WASM；预编译产物是否与源导出、严格解压 EOF 及版本一致 | 装配时验证成对资源、版本/校验值/导出与损坏/截断负向证据；不满足则最小修正解压适配并从匹配源码构建；不以历史资产清单证明当前可用 | AC-013 |
| H-PERF | 实时解码是否跟得上、录像耗时与最大文件 | 分别计时，记录丢弃帧/样本/失败，无已确认阈值只给测量值 | V-002、V-003；AC-012 |
| H-SAVE | 浏览器保存权限/运行时能力与关闭确认 | 能力检查；仅写入流关闭成功才标记保存完成；失败可重试 | AC-003、AC-009 |
