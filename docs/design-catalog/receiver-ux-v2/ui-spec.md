# 中文接收界面方案

[打开交互原型](prototype/index.html)。本地直接打开即可，不依赖网络。顶部固定标明演示数据；不会获取屏幕、读取录像或保存文件。原型不是产品实现，演示时间与百分比不作为验收记录。

## 设计上下文与平台

目标为宿主机桌面浏览器，鼠标/键盘操作，可调整窗口。沿用`web/desktop-recv/styles.css`的深色背景#111417、面板#1a1f24、青色#38b2ac、现有系统字体。布局增加状态与指标区域，不引入新导航体系或外部字体/图标库。

## 信息层级

1. 顶部保留“实时抓屏”“录像导入”两个入口，停止与保存按钮同行；活动期按旧规则互锁。
2. 主面板先显示清楚的一句话状态与原因，再显示码流重建估计。
3. 近期数据识别速率/接收用时作为次级指标，速率下始终说明含协议与冗余。
4. 录像会话额外显示“录像处理位置”，不合并为文件百分比。
5. artifact就绪后展示真实文件信息并强调保存；Saved与Ready文案分开。
6. 右侧操作建议讲下一步，输入预览放在次要位置，诊断日志可展开；常规使用不依赖英文日志。

## 状态矩阵

| 场景 | 主反馈 | 行为与数据 |
|---|---|---|
| 初始/准备 | 选择接收方式/正在准备 | 两入口保留；准备阶段展示实际等待含义 |
| 等待有效数据 | 不把有画面当已收到文件数据 | 速率0或采样中，未取得比例 |
| 正常推进 | 正在接收数据 | 估计、近期速率、用时 |
| 重复数据 | 暂时没有新进展 | 仍可有识别速率，比例不虚增 |
| 无新data | 最近没有识别到新数据 | 速率自然归零，上次比例加时间语义 |
| 多流/无报告 | 进度暂不可判定/暂不可用 | 仍展示有依据的速率和时长 |
| 理论数据量达到 | 继续补齐重建数据 | 不显示文件100%或硬停99% |
| 录像导入 | 正在读取录像并接收数据 | 媒体位置独立；耗尽无产物明确未完成 |
| 收尾 | 正在处理最后的数据 | 不提前启用保存 |
| Ready/Saving/Saved | 可保存/选择路径或保存中/已保存 | 来自三个不同真实阶段 |
| 保存取消/失败 | 文件仍在，可重试 | 无需重新接收 |
| 停止/未完成 | 明确本次结果及重开入口 | 会话清理后允许新开始 |

## 原型交互

- 点击实时抓屏：演示准备→等待→接收→可保存；点击录像导入：演示导入→可保存。不会打开系统选择器。
- “查看状态”可直接切换18个状态，包含等待、无新增、多流、报告不可用、理论数据量达到、录像耗尽和保存恢复。
- 点击保存进入模拟结算区，可选择成功、取消、失败；取消/失败后保存按钮恢复，成功后可开始新会话。
- 以上合成状态只用于评审布局和文案；原型没有复用真实接收器数据或计时，不能证明遥测正确性。

## 自适应与可访问性

760px以下右侧建议移到主面板下方；两个接收入口保留，操作按钮两列；380px以下指标单列。内容不要求横向页面滚动。按钮至少44px高、焦点可见；状态有文字，不依赖颜色；原型`lang=zh-CN`，语义状态区polite播报，指标区域不逐次live播报。正式实现应只对主语义变化播报，不能因每次百分比更新重复整段提示。

保存演示结果后把焦点返回可执行操作；实施时真实系统窗口的焦点行为仍须E2E验证。活动接收时输入预览保持可呈现，不采用会隐藏真实video的折叠控件，不得再次触发“隐藏preview导致rVFC停滞”的旧问题。原型预览区亦保持可见；结束后释放/隐藏沿用原生命周期规则。

## 评审与实施边界

本原型不直接替换`web/desktop-recv/`；布局/中文文案及状态层级供评审，字段与遥测退化已在[阶段2.5契约](module-contract-error-matrix.md)冻结。真实源名称、文件名、大小和错误信息必须来自实际对象，不照搬原型示例。真实UI应保留原数据/选择器/保存回归探针，升级依赖selector或英文status的测试时保持原断言含义，不为中文文案放松成功条件。
