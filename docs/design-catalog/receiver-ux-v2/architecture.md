# 增量架构与指标语义

## 结论与边界

接通已有Worker解码结果与report，增加会话内有界遥测，再由独立显示投影生成中文界面。保留实时抓屏、录像导入、停止、保存四类操作。解码业务保持现有状态/成功条件，UI不会因进度或时长自行判成功、失败或重启。

以下为设计，不是已实现代码；精确消息schema与边界已在[阶段2.5契约](module-contract-error-matrix.md)冻结，本页保留架构视角。

## 责任划分

| 组件/代码落点 | 设计责任 | 保持的原职责 |
|---|---|---|
| decoder-worker.js | 在本帧fountain_decode之后读取可选report；有界复制、解析/校验有限非负比例列表；随本帧结果携带可选观测 | 原解码、artifact构造、预算、严格EOF；report失败只标遥测不可用 |
| decoder-client.js | 将当前帧响应原样交给所有者；继续frameId对应与通道看门狗 | 不新增并行、不新增消息轮询；不在UI外推文件成功 |
| SessionCoordinator/session.js | 当前seq下消费data/no_data/artifact；维护遥测所有权与初始/终止时间，旧会话结果拒绝 | 唯一业务状态写者；不把遥测观察状态加入业务枚举 |
| 遥测模型（纯逻辑） | 有界速度窗口、最近数据/进展时点、质量/歧义状态、冻结时长；可由注入时钟测试 | 不访问DOM、WASM或选择器，不改旧stats含义 |
| UI投影/ui.js | 按业务状态优先级、观测与当前时间计算主文案、辅助提示、显示值 | deriveControls仍决定按钮权限；可显示值不反向驱动会话 |
| app.js | 低频绘制遥测区、触发中文主状态变化播报；绑定现有按钮 | 生命周期副作用保留在原事件路径；遥测tick不调用含业务副作用的整页render路径 |
| VideoSource | 沿用位置/时长快照，展示独立录像位置 | 不改变逐帧节奏/EOF/最后采样；不额外seek或加速 |
| SaveController | 向界面提供选择路径/写入/取消/失败/成功阶段 | 用户点击触发picker，write和close成功才Saved；重试使用原artifact |

## 事实与展示的分离

业务状态仍为Idle/Preparing/Receiving/Draining/Reconstructing/Ready/Saving/Saved/Retryable/Stopping/Stopped/Incomplete/Error。接收反馈是Receiving内的只读投影：

内部遥测有自己的observationRevision，所有权绑定sessionSeq；它不要求伪造业务状态变化来推进session.revision。业务事件过滤仍可沿用原规则，显示时钟则允许在同一业务revision下更新时长和窗口速率。新会话、旧结果与过期tick的检查先于任何显示更新。具体快照字段见阶段2.5契约。

| 实际观测 | 主提示/辅助提示 |
|---|---|
| Preparing | 正在准备接收；系统选择器仍由实际操作打开 |
| Receiving，尚无data/artifact | 正在等待有效数据；初期提示让发送画面可见，满5秒提示检查源和Mode B |
| 近期data、可用单流比例增加 | 正在接收数据；正常展示近期识别速率、时长与估计 |
| 近期data但可用比例8秒未增长 | 正在识别码流，暂时没有新进展；说明可能重复，建议保持发送端继续播放；不判故障 |
| 曾收到data，连续5秒无新data | 最近没有识别到新数据；检查源画面；保留最近估计并标“上次观测”，不宣称网络中断 |
| report缺失/无效、但data仍到达 | 正在接收数据；进度暂不可用；速率/时长仍可显示 |
| report多流/有效比例回退 | 正在识别码流；无法确定当前文件进度；不显示或沿用旧百分比，建议一次发送一个文件 |
| 当前帧自真实提交起处理≥1500ms且尚未回复 | 正在处理画面数据；普通短inFlight不覆盖正常接收提示，避免逐帧闪烁；计时继续 |
| Draining/Reconstructing | 正在处理最后的数据/正在重建文件；进度只能作先前参考 |
| Ready | 文件已接收完成，请保存；展示真实文件名和大小 |
| Saving(selecting) / Saving(writing) | 请选择保存位置 / 正在保存文件；不显示保存百分比 |
| Saved | 文件已保存；成功只来自write及close结算 |
| Retryable(cancelled) / Retryable(failed) | 已取消保存，文件仍可保存 / 保存失败，可重试；有artifact即可保持原重试规则 |
| Stopping/Stopped/Incomplete/Error | 正在停止/已停止/数据不足，未完成/未能继续；下一步动作按原权限给出 |

优先级：业务终态/保存态 > 收尾态 > Preparing > Receiving观测态。Receiving内先判超过1500ms的当前慢帧，再判无新data、遥测歧义/不可用、无进展、正常推进。普通inFlight不是主文案切换条件；慢帧状态不掩盖既有真正错误。

## 时间与速度

- 接收用时从进入Receiving开始，到首次Ready、Incomplete或Stopped/致命终结时冻结；不含选择源和保存等待时间。
- 同时保留主线程单调接收/最后结果/最后data/最后可信进度增长时点。可保留Date.now用于既有审计，但不拿它计算UI速率。
- 近期速率采用12个250ms时间桶，稳定实际覆盖2750～不足3000ms的data/artifact字节并除以实际窗口秒数；速率域前1秒显示“正在采样”。主单位KiB/s，说明“识别出的编码数据，含冗余”，不是原文件有效字节。错误/no_data/RGBA字节不计入。
- 无新data时窗口自然淘汰，3秒后速率归零；无样本与零速率区分。终止后显示冻结的接收用时，实时速度显示“—”，不继续运行虚拟流量。
- 时间桶、速率域预热/溢出重置、取整与时钟异常处理已在2.5固定；不使用无限数组，不因页面长时间隐藏进行无界补桶循环。

## 重建进度

1. 有效report是有限非负数字列表。一个活动流才可生成“码流重建进度（估计）”，未拿到artifact前不显示文件名或原文件总量。
2. 重复比例不虚增，不做时间插值，不用最高历史值掩盖回退。正常单流且0≤p<1时显示观测比例；比例持续不增长时提示事实。
3. p≥1时改为“已收集理论所需数据量，继续补齐重建数据”，使用不确定指示；不把100%当文件完成，也不硬夹99%假装能预测剩余。
4. 多流或已确认有效比例回退触发本会话歧义锁；后续列表变回一个值也不能证明其身份，因此本会话不恢复百分比。新会话重新建立观测。
5. report暂时缺失/解析失败时隐藏百分比并显示原因，后续同一未歧义会话可在有效报告恢复后重新展示；最后可信观测只作标明时间的参考。
6. 既有report是块ID去重比例，并不能证明完整文件恢复比例；唯一的接收完成信号仍是原artifact路径通过严格完成与预算校验。

## 录像位置

单独一行“录像处理到01:20 / 02:30”，由VideoSource实际位置提供；总时长不可靠时只显示已处理位置。不能把该百分比复制到文件进度，也不在media ended时直接庆祝完成。录像结束进入原EOF屏障，数据不足显示Incomplete；若文件先完成，允许提前结束读取并提示可保存。

## 刷新与生命周期参数

| 参数 | 初始设计值/规则 | 依据与性质 |
|---|---|---|
| 遥测重绘 | 最快250ms一次（≤4Hz），无变化不必写DOM | 降低重绘，不是吞吐承诺；设计选择 |
| 时长文字 | 跨秒更新；后台返回立即按当前时钟重算 | 不靠tick数计时 |
| 速率窗口/预热 | 3秒/1秒 | 平滑与及时性折中，阶段5实测可调 |
| 首次等待/无data提示 | 5秒 | 沿用现有提示意图，改为独立时钟触发 |
| 有data但无进展提示 | 8秒 | 提示而非失败门禁；设计选择，2.5记录常量 |
| 慢帧处理提示 | 1.5秒 | 主线程真实提交时点计时；普通inFlight不引起状态闪烁 |
| report缓冲 | 1024字节上限；碰上限按可能截断处理 | 现有最多8活动流；异常不放大内存 |
| 屏幕阅读器 | 仅主语义状态变化播报；不逐次播速度/百分比 | 减少高频打扰 |

独立刷新器仅在活动接收/收尾时存在；Ready/Stopped/Incomplete/Error、页面销毁时释放。新会话替换旧刷新器并绑定seq，回调发现过期不绘制。保存阶段由真实事件更新，不需持续接收tick。window隐藏时浏览器可能节流，不承诺精确定时回调；返回前台按实际时间恢复正确值。
